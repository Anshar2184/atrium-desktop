**4.9 接管协议 v2（`p07c`）**——Guard 为 C++ 原生程序（275 KB，只依赖 USER32 / SHELL32 / KERNEL32，Per-Monitor V2 DPI）。Core 先等 Guard 的就绪握手，再在接管锁内依次执行三步：切自动隐藏 → 注册真实的底部 AppBar（56 px，工作区底边从 1904 变为 1944）→ 隐藏任务栏。每一步先检查撤销标志，再写恢复状态，再执行。恢复只有在核实任务栏可见、自动隐藏回到用户设置、工作区与接管前一致、Core 不再持有 AppBar 之后才写 `restored`。

| 场景 | 注入方式 | 恢复耗时 | 恢复者 | 结果 |
| --- | --- | --- | --- | --- |
| R1 强杀 Core | 结束进程 | 395 ms | Guard（进程退出），替已死的 AppBar 撤销保留区 | ✅ |
| R2 Core 卡死 | 主线程永久休眠 | 3.62 s（含 3 秒判定） | Guard：撤销 → 结束 Core → 恢复 | ✅ |
| R3 注册 AppBar 后崩溃 | `FailFast` | 3.07 s | Guard（错误报告使进程多存活，由心跳发现） | ✅ |
| R4 正常退出 + 两次并发手动恢复 | 4 个恢复同时发生 | 453 ms | 只执行一次，其余 3 个返回“无事可做” | ✅ |
| R5 Guard 被杀 | 结束 Guard | 439 ms | Core 先交还 AppBar，再调用 `--restore` | ✅ |
| R6 两者同时被杀 | 结束两个进程 | 1.15 s | 下次启动按残留状态恢复 | ✅ |
| R7 Guard 初始化失败 | 故障注入：控制块映射失败 | — | Guard 不发布就绪；Core 18 ms 后放弃，**全程**系统状态未变（50 次采样） | ✅ |
| R8 启动阶段停顿 | 就绪后、第一步前停 5 秒 | 2.65 s | Guard：判定卡死 → 结束 Core | ✅ |
| R9 停顿后恢复执行 | 隐藏任务栏前停 5 秒；故障注入：Guard 不结束 Core | 4.86 s | Guard 撤销并恢复；Core 恢复执行后下一步被拒绝、交还 AppBar 退出，**未再隐藏任务栏** | ✅ |
| R10 在锁内停顿后恢复执行 | 注册 AppBar 步骤持锁停 5 秒；Guard 不结束 Core | 4.97 s | 同上；Guard 等锁后恢复 | ✅ |
| R11 恢复期间 Explorer 不在 | 故障注入：找不到任务栏窗口 | Guard 8.25 s 后放弃 | Guard 写 `restore-pending`（`shell-missing`）、退出码 3；下一次恢复成功 | ✅ |
| R12 Explorer 2 秒后才出现 | 故障注入 | 2.48 s | Guard 有界重试 9 轮后完成 | ✅ |
| R13 恢复操作未生效 | 故障注入：设置自动隐藏无效 | Guard 8.28 s 后放弃 | 写 `restore-pending`（`autohide-mismatch`）；下一次恢复成功 | ✅ |
| R14 接管锁被占用超过 10 秒 | 另一进程持锁 14 秒 | 14.4 s | Guard 返回 `lock-unavailable`，**未改动**状态文件（仍为 `active`）和系统；锁释放后手动恢复成功 | ✅ |
| R15 Core 持锁时被杀 | 隐藏步骤持锁停顿时结束 Core | 371 ms | Guard 取得**废弃锁**（`abandoned=1`）后恢复 | ✅ |

判定条件：恢复后自动隐藏、任务栏可见性、工作区与测试前完全一致；恢复之后持续采样直到两个进程都退出、再观察 1.5 秒，任何一次偏离都算失败（全部为 0）；状态文件阶段与恢复者符合预期。最后恢复用户真实设置并核对。

本轮测试自身发现并修复了 3 个缺陷：
1. **Guard 没有 DPI 感知**：在 200% 缩放下读到的工作区是 `0,0,1600,952`，与 Core 记录的物理像素不一致。旧版 Guard 不核实恢复结果，所以从未暴露；新版因此全部写成 `restore-pending`。已改为 Per-Monitor V2。
2. **恢复持锁等待 Core 交还 AppBar，而恢复执行的 Core 需要同一把锁才能看到撤销**：两者互等到 8 秒上限（R9/R10 首次失败）。改为先撤销、在锁外等待 Core 退出，再持锁恢复。
3. **正常退出时 Core 等待 `--restore` 期间停止心跳**，被 Guard 误判为卡死并结束。改为等待期间继续心跳。

R11–R13 的 Explorer 缺失和操作不生效是 Guard 内的故障注入（`ATRIUM_GUARD_FAULT`），没有真的结束 Explorer。第二轮的 T1–T6（`p07b`，协议 v1、不含 AppBar）已被本表取代，原始数据保留。尚未覆盖：渲染线程卡住但 UI 线程仍有心跳、Explorer 真实重启、睡眠唤醒、系统更新、多屏。

过程中发现：在处理另一个进程发来的托盘消息时，再向卡住的目标调用 `SendMessageTimeout`，实测会等满 3 秒才返回成功，500 ms 超时没有生效；单独的同进程和跨进程嵌套调用都无法复现，根因未查明。因此改为“负载拷贝 + 每个目标一个转发线程 + 桥接线程自行限时等待”，上限不依赖该 API 的超时行为。Explorer 重启、真实应用的兼容矩阵仍待测。

实现要点：
1. 层级（D25）：WinEvent（前台切换、窗口移动结束，进程外）+ 每秒检查。只在“其他进程的可见置顶窗口与栏重叠且在栏之上”时提到最上，菜单、提示、输入法、外壳面板、点穿覆盖层、隐藏（cloaked）窗口不算；同一窗口 10 秒内第 5 次盖上来就让它留在上面，避免两个置顶窗口互相争抢。全屏判定：前台窗口覆盖栏所在的整块显示器、不是最大化、不是桌面或系统任务栏（自动隐藏任务栏下最大化窗口也覆盖整屏，所以必须排除最大化）。
2. 统一材质（D26）：弹出窗口有两个 DComp 目标——非置顶层是玻璃（栏的渲染线程、同一个 WGC 捕获、同一个着色器、同一硬件设备，不另建设备），置顶层是 Direct2D 内容（WARP）。玻璃按下方平均亮度把染色加深到文字可读（实测开始菜单与通知 0.64）。弹窗始终排除在屏幕捕获之外（否则玻璃会采到自己的文字）。
3. 动效（D27）：放大用连续的升余弦缩放密度并从指针处积分得到显示位置，指针下的图标保持不动，基础布局的命中测试仍然准确；玻璃形状由着色器参数（形状矩形）实时伸展，不改窗口大小；窗口为放大与弹跳预留上方空间，输入区域只在悬停时向上扩展。弹窗开合用 DComp 动画（DWM 驱动，与内容帧率无关），内容层的逐项淡入、悬停、滚动用计时器逐帧绘制。

开发中发现并修复：
1. 逐项淡入最初用 D2D 图层（`PushLayer`），WARP 会缓存图层表面：开始菜单打开时内存 152 → 239 MB，关闭后 228 MB。改为把透明度乘进画刷与位图，并且弹窗的玻璃渲染器不再创建用不到的 D2D 设备，降到 17.7 的数值。
2. 开始菜单在 `--command` 触发的跨进程 `SendMessage` 中打开时，网络列表（COM 调用）读取失败，显示“未连接”；改为打开后 50 ms 再读一次状态。
3. 账户头像起初按“图标”取图，显示成图片文件的图标；改为取缩略图。
4. 弹窗第一帧先于弹出动画呈现，可能闪一帧完整画面；改为先设好动画再画第一帧。
5. 测试本身：子进程测试窗口未声明 DPI 感知，200% 下坐标被放大一倍、窗口落到屏幕外，“置顶遮挡”测试误判失败；测试窗口改为 DPI 感知并核对它确实与栏重叠。设置中心测试第一次运行时用户自己的设置中心窗口仍开着，单实例转交导致取不到窗口，关闭后重跑通过。

限制与未做：
- 自动隐藏的系统任务栏升起时栏让到它下面；非自动隐藏的系统任务栏不与栏重叠，不涉及。
- 全屏判定只看前台窗口；全屏窗口在另一块显示器时栏不隐藏（多显示器本轮仍未做）。
- 提示文字仍是系统提示框，没有改为玻璃标签。
- 弹出窗口的阴影边距（12 DIP）在窗口内，点在这条边距上会关闭开始菜单 / 通知列表，但点击不会穿透到下方窗口。

开发中发现并修复：
1. 开始菜单固定项缺失：Core 若从缺少 `ALLUSERSPROFILE` 的环境启动（本机日常的 Core 就是这样启动的），`ExpandEnvironmentStrings` 原样保留 `%ALLUSERSPROFILE%`，17 个快捷方式被判为不存在且静默跳过。改为用已知文件夹（`SHGetKnownFolderPath`）展开，并记录无法解析的固定项。
2. 浅色背景文字看不清：深色墨的切换阈值过高，浅灰窗口（0.5–0.65）上仍是白字。
3. 栏让位给系统任务栏的规则过宽：QQ 闪烁任务栏按钮时自动隐藏的系统任务栏一直升着，栏一直被压在下面（日志每秒一条）。改为只有用户在用系统任务栏（指针在系统任务栏上且不在栏上，或焦点在系统任务栏 / 溢出窗口）时让位；第一版把“指针在系统任务栏矩形内”算作在用，而升起的系统任务栏与栏重叠，指针放在栏上也算，测试中所有点击都落到了系统任务栏，改为排除栏的区域；让位期间每 150 ms 检查一次，指针回到栏上立即恢复。
4. 托盘 Invoke 后 Explorer 把焦点交给隐藏的溢出窗口：它让系统任务栏保持升起，并像轻量弹出窗口一样吞掉下一次点击。点击后 600 ms 若焦点仍在隐藏的溢出窗口，交还给打开面板前的窗口；`AttachThreadInput` 后的 `SetForegroundWindow` 仍被拒绝，改为先发送一次 Alt 键再设置（实测成功）。
5. 栏宽设得很小时（300 DIP）固定部分放不下，溢出入口被挤成 17 px：栏宽下限改为固定部分的宽度。
6. 测试设置文件没有 `version` 字段，新默认值会打开 Windows 通知与微信来源，真实消息会干扰计数：各测试显式关闭两个来源。

限制与未做：
- 托盘无法转发双击；应用若按随消息传来的坐标放菜单，菜单出现在屏幕左下（隐藏溢出按钮的位置）。图标图片来自 Windows 的托盘记录（快照可能不是最新状态的图标），无记录时用程序图标。
- Wi-Fi 列表依赖 WLAN API；Windows 11 关闭“允许桌面应用访问位置”时可能读不到网络名称（本机可读）。连接新网络（需要密码）交给系统的网络列表。
- 微信来源只看得到微信已生成的约十个会话行，微信窗口需要打开过一次；免打扰会话不提醒；实机出卡待验证。
- 系统通知横幅仍会出现（Atrium 不改用户的通知设置）。
