# VERIFICATION · 可行性验证清单

执行日期：2026-10-31。执行方式：`poc/` 下的探测程序（C# / .NET 8 + Vortice D3D11 + 原生 Win32/WinRT 接口），在真实交互桌面上运行。每项结果的原始数据在 `poc/results/*.json`。

> 原型用 C# 写，是因为这台机器没有 C++ 工具链，而安装 Visual Studio Build Tools 需要管理员授权。验证的对象是 Windows 本身的行为（捕获、合成、Shell、托盘、输入），这些与语言无关；产品核心仍按 [TECH-DECISIONS](TECH-DECISIONS.md) 使用 C++20。

图例：✅ 已验证可行 · ⚠️ 可行但有限制或需要替代方案 · ❌ 不可行（已给出替代方案） · ⬜ 本机无法验证

## 1. 实时玻璃渲染（P01）

| # | 验证项 | 结果 | 关键数据 |
| --- | --- | --- | --- |
| 1.1 | `WDA_EXCLUDEFROMCAPTURE` 让窗口从 WGC / DXGI / GDI 捕获中消失，且看到的是下方真实内容 | ✅ | 排除后三种捕获中窗口像素占比 0，与无窗口基线差异 0，无黑块 |
| 1.2 | D3D11 + DirectComposition 预乘透明交换链渲染液态玻璃，60 fps | ✅ | 核显 666 帧 / 独显 631 帧，无闪烁 |
| 1.3 | GPU 成本（背景 ROI 拷贝 + mip + 玻璃着色，1500×196 胶囊条） | ✅ | 核显 0.16 ms/帧，独显 0.04 ms/帧（目标 ≤ 3 ms） |
| 1.4 | 同一引擎在 Liquid 与 Frosted 之间平滑切换，不重建设备 | ✅ | 900 ms 参数插值，见 `docs/images/` |
| 1.5 | 动画时 CPU | ✅ | 整机 0.23%–0.75%（.NET 原型） |
| 1.6 | 自回声：玻璃自身 Present 会触发新的捕获帧 | ⚠️ 已确认存在 | 静止时捕获 45–53 fps（无玻璃时 2 fps），脏区域全部落在玻璃内 |
| 1.7 | 自回声过滤：脏区域全在玻璃内时比较背景低分辨率 mip，未变化就不重绘 | ✅ | 捕获降到 8 fps、CPU 0.04%–0.07%；玻璃下方 12 次真实变化全部重绘 |
| 1.8 | 新帧到达到玻璃 Present | ✅ | p50 0–15 ms，p95 16 ms（一个刷新周期） |
| 1.9 | 内置截图：捕获帧 + 离屏渲染玻璃合成完整画面 | ✅ | 合成图与用户所见一致；系统截图中玻璃不可见（符合预期） |
| 1.10 | DXGI 桌面复制 | ⚠️ | 进程在独显上时 `DXGI_ERROR_UNSUPPORTED`；切到核显后正常 |
| 1.11 | WGC 无黄色边框（`IsBorderRequired = false`） | ✅ | 默认边框时窗口边缘 67% 为黄色，关闭后 0；未弹授权（仅本预览版确认） |

**决策**

- 主捕获后端用 **WGC**；DXGI 只作对照，不进生产。
- **渲染设备必须建在实际输出画面的适配器上**（本机为核显）：DXGI 才可用，也避免跨显卡拷贝和唤醒独显。安装时为 Atrium 写入“节能 GPU”偏好或运行时按输出 LUID 选适配器。
- 自回声过滤是必需功能。产品中把同步回读改为异步小纹理环形缓冲（本原型同步回读 p95 2.5–3.7 ms）。
- 核显上直接渲染进交换链时，计时包含约一帧的缓冲等待；产品使用帧延迟等待对象或 3 缓冲。

## 3. 输入与命中测试（P02）

| 方案 | 结果 | 说明 |

## 10. 对系统的影响与恢复记录

- 在用户目录安装 .NET 8 SDK（`%LOCALAPPDATA%\atrium-tools\dotnet`），无管理员权限，删除目录即可卸载。
- 临时写入 `HKCU\...\DirectX\UserGpuPreferences` 中探测程序自身的 GPU 偏好，每次运行后删除；已核对为 0 条残留。
- 隐藏任务栏、切换自动隐藏、Win+D、模拟点击：均在用户空闲时执行，结束后核对任务栏可见、置顶、自动隐藏设置与工作区，均与测试前一致。
- ManagedShell 测试把 Explorer 任务栏的置顶属性改掉，已立即修复并核对。
- 一次测试后键盘焦点停在 Explorer 的不可见托盘溢出窗口上，已把焦点还给用户窗口；之后逐项复现均未再出现，原因未定，产品中会主动记录并恢复焦点。
- 结束时核对：无残留进程、无残留窗口、无残留注册表项。
