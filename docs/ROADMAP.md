# ROADMAP

状态：P00–P07 的首轮原型已于 2026-10-31 执行（单屏、预览版 build），结果见 [VERIFICATION](VERIFICATION.md)；多屏、HDR、Explorer 重启、睡眠和长时间稳定性仍待执行。只有架构评审通过后才开始产品编码。顺序由风险决定：捕获/恢复/托盘/通知身份/桌面层先行，视觉页面后置。不能在前置闸门失败时继续堆外观掩盖问题。

## 1. 已知环境与执行规则

2026-10-31 只读核实注册表 `DisplayVersion=26H2`、`CurrentBuild=26300`、`UBR=9711`。ProductName 返回旧字符串 Windows 10 Home China，不能单靠它否定 Win11 build；实施前用 winver、OS build、更新通道共同确认。本次没有认证其公开发布渠道或稳定支持状态。

已枚举显卡与驱动：Intel Arc 31.0.101.5008；NVIDIA RTX 4060 Laptop 32.0.16.1062；GameViewer Virtual Display Adapter 15.6.5.199。CPU Ultra 9 185H、32 GB、3200×2000/200% 为用户提供，尚未另行实测确认。显示输出到底连接哪个适配器、HDR/刷新率和 MUX 状态仍待 P00。

每个 PoC 输出独立 exe/工程、README、result.json/CSV、trace、成功和失败画面、操作步骤。结果记录 OS/SDK/compiler、commit、GPU LUID/driver、显示器标识/模式、DPI、电源模式与权限状态；不能仅贴一张成功截图。交互式试验须保持可见恢复入口，不在登录时自动接管。

## 2. 独立技术验证

### P00 · 环境与可复现基线

步骤：枚举 DXGI 输出/适配器、QueryDisplayConfig、DPI、刷新率、HDR；记录本机信息；选一个受支持稳定版 Win11 物理测试环境作对照。记录无 Atrium 时静止/视频/游戏的 CPU、GPU、功耗。

通过：每个显示输出能追溯至 LUID/设备路径；构建工具链版本可复现；本机与稳定版测试角色明确。失败备选：先仅内屏 SDR；虚拟屏作为独立不支持项。交付：environment.json、基线表、锁定工具链提案。

### P01 · 实时背景与双材质（最高优先级）

步骤：不隐藏系统任务栏，创建一块 D3D11 玻璃测试窗；WGC 与 DXGI 分别捕获同屏；设置 WDA 排除并验证返回；背景运行帧计数网格、滚动网页、视频；拖动透镜、调模糊/圆角/折射/色散、切换 Frosted/Liquid 100 次。分别测试普通截图、OBS、锁屏、UAC、捕获权限拒绝。切换电源模式、再加外屏/虚拟屏，不能只跑静态壁纸。

通过：无自反馈、黑块、残影；原始背景真实改变；切换无 device 重建闪屏；满足渲染文档单屏目标，并报告 WGC 与 DXGI 的 p50/p95/p99、功耗及队列深度；普通录屏的缺失行为被记录而非隐瞒。静态 10 分钟不持续自激重绘；真实背景在玻璃覆盖范围内变化不可漏更新。

失败备选：WGC 若边框/功耗失败但 DXGI 通过则选 DXGI；两者都失败则发布壁纸玻璃/染色降级，**停止承诺实时 Liquid**。截图可见为硬要求时先启用录屏兼容模式。交付：capture-glass.exe、对照 trace、视觉验收表、后端决策。

### P02 · D3D11 合成宿主与输入

步骤：相同 shader/surface 分别接 DComp 和 Windows.UI.Composition；如需评估 App SDK 再加 Microsoft.UI.Composition 对照。验证 premultiplied alpha、圆角、阴影、DirectWrite、中英文/emoji、surface resize、拖屏 DPI、动画和失效重建。点击阴影/透明角落下方其他进程的应用，键盘操作和读屏。不得同时混用不同命名空间 visual 对象。

通过：透明边缘无黑边；玻璃外点击真正到达下方应用；玻璃内动作正确；焦点可预测；100/125/150/200% DPI 字形清晰、命中不偏；D3D11+Windows Composition 成功互操作并给出相对开销。DComp 稳定则保持默认，不能因对照存在就把两套宿主带进生产。

失败备选：DComp 路径保留；输入需要时采用独立精确输入 HWND；Windows Composition 对照失败不阻断 DComp 架构。若透明合成全失败则停止视觉开发。交付：宿主对照、输入矩阵与选型更新。

### P03 · 任务栏隐藏、AppBar 与共存

步骤：先实现最小独立 restore 工具并验证有效；保存原任务栏状态；先建可用 Atrium 测试栏，再试隐藏主/副系统栏及工作区协商；测试自动隐藏、最大化、贴靠、Win 键、Win+S/A/N、显示桌面、三屏、断开显示器、Explorer 重启。与另一个占底边 AppBar 的冲突作为负向场景。

通过：无需终止 Explorer/管理员；工作区无重复保留/残留；100 次进入退出接管成功，所有屏原状态可恢复；系统入口能从栏访问；不持续抢占全屏窗口。任何不可恢复或卡死算失败，不能靠重启电脑算通过。

失败备选：保留原栏并做共存；自动隐藏边冲突时关闭替换模式。交付：taskbar-recovery PoC、状态前后快照、系统入口行为表。

### P04 · 托盘与任务模型

步骤：独立桥接实验对照 Explorer 原生托盘；读取 ManagedShell 实际启用路径，记录私有 API/跨进程访问/设置修改。覆盖已在运行的图标和新启动图标、GUID 图标、隐藏区、tooltip、左右键/双击、菜单焦点、提权程序、x86/x64 客户端、DPI 和多屏。用受控示例客户端加本机常用音乐/通讯/云同步/输入法；窗口分组覆盖多窗口、UWP/packaged、浏览器、重启及标题变化。分别杀 bridge/Core，再重启 Explorer。

通过：预先列明的必需应用全部可见可操作；无丢图标、误激活、双 host 竞争；恢复后无需用户重启第三方应用；不需要全局注入、关闭安全功能或私有系统文件修改。列明覆盖范围，不宣称所有应用 100% 兼容。

失败备选：原生托盘入口临时恢复完整原栏；若必须无缝一体托盘则该需求阻断。不要把兼容层失败转为“自己完整实现 Shell 协议”。交付：兼容矩阵、bridge 副作用表和是否引入依赖的决定。

### P05 · 包身份、通知监听与右下角面板

步骤：制作带正确 capability 的最小签名 MSIX，Settings/Core 分别检查真实 package identity；在 UI 线程请求权限，测试拒绝/撤回/重新允许。由受控发送器发有文本、图像、按钮、更新/替换/过期的 Toast，再覆盖实际第三方应用与自绘通知；记录 native banner 出现时刻、Listener 事件和列表时刻；测试 DND、锁屏、离线、重启、每应用关闭 banner 保留中心。

通过：授权链可解释，撤权无正文泄露；初始同步不全部当新事件弹出；事件重复/ID 复用不造成重复；右下角展开/合并状态正确；不能执行的第三方动作不显示伪按钮。明确证实监听不是 pre-toast 拦截，并标出不可见通知类别。默认补充模式无额外自动弹窗。

失败备选：只显示 Atrium 自己的事件，提供 Win+N 入口；MSIX 组合不可用时可独立验证 identity package，但不写数据库补救。交付：权限/时序矩阵、包方案和能力说明。

### P06 · 桌面层、Win+D 和自捕获冲突

步骤：一个时钟 HWND 在公开 top-level 与实验 WorkerW child 两种模式对照；测试连续 Win+D 100 次、桌面图标交互、应用遮挡、虚拟桌面、Explorer 重启、睡眠、不同 DPI、桌面父窗消失。对子窗口尝试排除时记录 API 结果，验证实际画面；分别选择屏幕来源与壁纸来源，观察前景应用污染。

通过：选定模式不长期覆盖应用，不挡图标点击，布局可恢复；实验 child 必须在全部目标 build 通过且关闭时不改坏 Explorer。实时采样若不正确就明确禁用，不能以壁纸结果通过实时玻璃指标。

失败备选：普通桌面工具窗、Win+D 时随系统隐藏，或禁用桌面常驻；保留手动打开的小组件面板。桌面层持续可见若是不可调整硬需求则停止该功能发布。交付：层级图、行为视频与模式决策。

### P07 · Guard 故障恢复（接管发布阻断项）

步骤：在 P03 的最小栏上注入 Core exit、abort、UI 死循环、render 卡住、device lost、bridge crash；分别在 prepare/takeover/active/restore 阶段强杀。随后测试 Guard 退出、Core+Guard 同时终止、断电等价的遗留日志、休眠唤醒、Explorer 重启、更新/卸载。

通过：单 Core 退出/崩溃目标 2 秒内恢复原栏；UI 卡死目标 5 秒内恢复；其他故障允许明确的降级但不出现不可操作桌面。每个关键场景 100 次无失败，恢复幂等；恢复入口不需要 D3D/.NET；双方终止场景不能虚报即时恢复，验证下次启动修复与手动 --restore。

失败备选：禁止隐藏原生任务栏，保留共存。交付：故障注入表、恢复延迟直方图、遗留状态验证。

### P08 · 设置、配置迁移与无障碍

步骤：最小 WinUI 页通过管道改变真实材质；连续拖动滑块、断开 Settings、并发 revision 冲突、保存时终止 Core、损坏配置、升级/降级 schema。测 Settings 冷启动和退出后无残留；测试 Narrator、键盘和高对比。初始安装的签名/权限流程全程走一遍。

通过：预览 ≤下一到两帧响应，提交持久化可确认；失败不损坏上版配置；Core 独立运行；未知新 schema 不被覆盖；所有关键任务栏动作可键盘访问。交付：协议、migration fixtures、操作演示。

### P09 · 性能与长期兼容验收

步骤：单屏基线、多屏混合 DPI/刷新率、iGPU/dGPU 输出、HDR、虚拟屏、全屏/无边框游戏、远程会话、睡眠 50 次/外屏热插拔 50 次。先 8 小时稳定测试，候选版再 72 小时日常混合负载。检查 GDI/USER 句柄、线程、private bytes、GPU 内存和设备重建次数。

通过：满足渲染预算；无持续资源增长（以预热后趋势和峰值稳定为准）；无任务栏恢复失败、焦点劫持或通知隐私泄露；每种降级状态在 Settings 可见。未通过的配置进明确 unsupported/degraded 名单。

失败备选：按屏关闭 capture、降低分辨率/帧率、Frosted/壁纸/不透明、安全共存。不得以“测试机性能强”跳过电池验收。

## 4. 测试结果格式

每个 result 文档记录：假设、证据链接、固定源码版本、环境、执行步骤、预期、实际、指标定义、失败日志、回退验证、结论和评审人。结论只能是 Passed / Failed / Inconclusive；缺少硬件或无法测量写 Inconclusive，不能写“应该可用”。每个关键决策更新 TECH-DECISIONS 信心，新的私有 API 必须进入 RISKS。
