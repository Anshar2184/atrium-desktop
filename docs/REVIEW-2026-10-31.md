# 首轮验证审查

审查基线：`afdd3ec`，2026-10-31。范围：更新后的架构文档、PoC 源码与已提交 JSON；独立构建两个 .NET 工程。结论：**基本技术路径已有证据，可继续原型迭代；暂不通过系统接管的完整架构冻结。**

没有重新执行会隐藏任务栏、接管托盘、模拟点击或改变桌面状态的探测程序；不把历史 JSON 当本次独立实测。未修改现有代码和报告，仅增加本审查文件。

## 发现（按优先级）

### 1. [P1] Guard 测试未覆盖新增的自动隐藏回滚，不能据此关闭恢复风险

位置：`poc/Probe/TaskbarProbe.cs:116`（Restore）、`:163`（WaitForExit）；`docs/VERIFICATION.md` 第 4 节。

Restore 只按窗口类恢复可见性，未恢复快照中的 autoHide。强杀测试的 before.autoHide 本来就是 true，而修改自动隐藏的 RunNoAutoHide 是另一个正常返回试验。因此“自动隐藏 + 接管 + 强杀 + 恢复原用户设置”尚未作为完整事务测试。用户原本非自动隐藏时，在切换之后崩溃会留下错误设置。Guard 还只等待进程退出，活着但 UI/渲染卡死不会触发；文档中的原生、无 .NET Guard 是产品设计，当前实际运行的 tbguard 仍是同一个 framework-dependent .NET EXE。

要求：建立一条统一接管事务，Guard 读取其持久恢复状态；增加 autoHide=false 下切换后强杀、UI 卡死、启动中途失败及恢复重入测试。128 ms 只保留为“本次已自动隐藏配置下单次强杀恢复可见性”的观测，不代表 P07 完整通过。

### 2. [P1] 回声过滤更新未呈现帧的签名，缓慢变化可能永久漏绘

位置：`poc/Probe/GlassRenderer.cs:200–201`；调用阈值在 `GlassProbe.cs` 的 phase2b。

BackdropChanged 无论是否返回 changed 都执行 `_lastSig = sig`，阈值为 6。当每帧颜色变化 1 时，每次都只和前一捕获帧比较，永远不超过阈值；即使累计变化达到 120，仍可没有任何重绘。低 mip 还会稀释细线/小文本变化。现有 160×90 大色块的 12 次强对比翻转不能证明真实变化不会丢失，echoDrawn 数量也没有逐个匹配每次 flip。

本次对源代码的比较规则做无 GPU 数值反例：初值 0，连续 120 帧每次 +1，阈值 6，结果 redraws=0、最后呈现值=0、当前值=120。它验证逻辑缺陷，不是一次 GPU 实测。

要求：比较基准关联最近实际呈现的背景，只在确认使用该帧绘制后提交签名；加入最大陈旧时间，并针对细小变化补 tile/更精确检测。测试慢渐变、低对比滚动文字、1 px 光标、短暂出现后消失的内容，保留每次变化的 ID 与呈现记录。修正前将“过滤可保证真实变化仍绘制”降为部分验证。

### 3. [P1] 托盘转发失败仍返回成功，无法保证 Explorer 同步

位置：`poc/Probe/TrayHost.cs:44–50`。

SendMessageTimeout 失败/超时后只累加 forwardFailed，然后返回 1。此时调用方被告知成功，Explorer 却可能未保存该图标；桥接退出后图标丢失，恰好违反此次转发桥接的核心目标。同一窗口过程还同步等待 Explorer 最多 2 秒，故“消息线程绝不阻塞”不能由本原型支持。44 条正常消息零失败只验证正常路径，没有验证 Explorer 卡住/失效路径。

要求：明确转发成功、失败、超时后结果不确定的协议语义，不能默报成功；设计有界等待、失效退出/恢复与重同步。不能简单把 WM_COPYDATA 的借用指针丢给异步任务。补测受控目标无响应、失效句柄、bridge 中途退出与消息突发，并核实客户端返回值和 Explorer 最终图标状态。自写相同类名与消息格式仍是 Shell 兼容技巧，不因改用 C++ 就成为受支持的托盘接管协议。

### 4. [P2] 桌面层验证没有实现所宣称的前台事件驱动逻辑

位置：`poc/Probe/DesktopProbe.cs:93–102`；`docs/TECH-DECISIONS.md:29`。

测试自行发送 Win+D，固定等待后把 widget 设为 HWND_TOPMOST；再发 Win+D，固定等待后手动撤销置顶并压底。程序没有注册 EVENT_SYSTEM_FOREGROUND，也没有判断“用户退出显示桌面”的状态机。它证明手动升降能改变可见性，不能证明真实用户打开应用、点击任务栏、焦点落到 widget、桌面图标交互时会自动降层。

要求：把结论改为“顶层窗口升降原语可行，自动桌面生命周期未验证”；实现真实事件驱动试验，再覆盖 Win+D、鼠标显示桌面、从桌面启动应用、窗口恢复、焦点转入 widget 和启用桌面图标。不能据当前结果将桌面层风险标记为已解决或据此排除所有替代方案。

### 5. [P2] 方案 C 只验证静态合成，尚未证明截图可见的实时玻璃

位置：`poc/Probe/OptionCProbe.cs:86–107`；`docs/VERIFICATION.md:56`。

代码选择没有普通应用遮挡的区域，只加一个自有单色测试窗口；读取 desktop/app 一次，CPU 合成一次并上传固定纹理。随后 20 次 Present 均未更新背景。它支持“受控静态场景可以合成并出现在 GDI 截图”这一结论，不支持多窗口实时背景重建。缺少动态 Z-order、窗口移动/resize、内容同步、alpha、窗口新建/销毁；这些是主链路而不仅是 DRM 等边缘场景。

要求：方案 C 保留实验候选，先用两个持续更新且相互遮挡的窗口验证重排、移动与帧一致性，再加真实应用/菜单/透明窗。输出动态误差和延迟，而不只全 ROI 平均误差。README 的 ordinary screenshot works 应注明“静态受控 PoC”。

### 6. [P2] 性能通过结论混用了离屏平均吞吐、帧延迟和 p95

位置：`poc/Probe/GlassProbe.cs:80,143`、`poc/Probe/Wgc.cs:135`；`poc/results/p01b-glass-igpu.json`；`docs/TECH-DECISIONS.md:27`。

核显 update/draw timestamp 的 p95 都是 0，gpu-budget 因而回退到 300 次离屏批处理的平均吞吐 0.158 ms；它没有验证实时 p95 ≤3 ms，且不涵盖捕获回调全屏 CopyResource、签名 Map 或合成显示。现有 JSON 的 phase1 frameAge p95=125 ms 且 verdict=Inconclusive，不能以 phase2b arrivalToPresent p95=16 ms 代替整体动态背景延迟。

LastFrameTicks 在等待 context 锁并复制之后才记时，排除了 callback 等锁时间；时间戳、帧计数、dirty 信息和纹理没有作为同一带序号快照返回，采样到的时间可能并非实际绘制纹理对应时间。Present 返回也不是屏幕已经显示。

要求：保留 0.158 ms 为离屏均摊吞吐参考，将实时 p95 达标改为待证；帧附 source timestamp/arrival/copy/render/present 与 frame ID，元数据和纹理一起交付，持续变化背景下测量。加入完整 update+filter+draw 实时分位数及可见延迟。文档的签名回读 p95 2.5–3.7 ms 也与当前核显 JSON 4.144 ms 不一致，应同步。

### 7. [P2] 通知包身份因果尚未验证，却被提升为确定选型结论

位置：`poc/Probe/NotifyProbe.cs`、`docs/TECH-DECISIONS.md:30`、`docs/VERIFICATION.md` 第 8 节。

代码只记录此环境 GetAccessStatus 为 Allowed、读数量成功、订阅抛出 0x80070490；没有请求/撤销授权、没有验证实际包身份，也没有同代码的 packaged 对照。一次 HRESULT 不能单独证明错误唯一来自未打包，更不能证明加 sparse identity 后事件链就会成功。“首版不做通知中心”可以是范围选择，但不应写成已完成通知身份验证后必然得出的结论。

要求：状态改为“本机当前权限下可读；事件订阅失败，包身份方案待对照验证”；未来补身份检测、MSIX/sparse package、授权/撤权和新 Toast 事件观测。若本阶段主动推迟通知，P05 标为部分执行/延后。

位置：`docs/ARCHITECTURE.md:5,13`、`docs/TECH-DECISIONS.md:14,28`、`docs/PROJECT-STRUCTURE.md:38`，以及 WINDOWS-INTEGRATION 的托盘/桌面章节。

## 已有证据可以支持什么

- 本机 SDR 单屏可运行 WGC + 排除 + D3D11/DComp 玻璃管线，双材质共用 renderer 的方向合理。
- 输入拆窗方案在已有几个命中点测试中得到支持，可作为优先方案；仍需与捕获排除、真实内容和完整交互一起集成验证。
- 原栏隐藏、工作区协商、原生面板入口、用户点击后激活、DWM thumbnail 的基础调用已有结果。
- 转发桥接的正常路径比当前测试的 ManagedShell 直接接管更接近共存目标，但错误路径和老图标兜底尚未完成。
- C# 用于行为 PoC 可以接受；不能由此声称原生 Guard、C++ 工具链或生产长期性能已经验证。
