## 2. 发布硬门槛

- 任一任务栏接管版本必须通过故障恢复矩阵；否则接管开关不可用。
- 全一体化第三方托盘需要具体兼容清单和恢复证据；“已有成熟库”不能豁免。
- 第三方通知默认不自动重复弹出；权限撤销、锁屏、默认不落盘必须验收。
- 不支持的显示配置允许降级，但不可黑屏/遮挡输入/循环重启。
- 不能宣称 macOS 级别视觉/功耗/延迟，除非有预先定义并实际执行的比较记录。
- 不允许安全功能关闭、系统文件替换、终止 Explorer 或全局注入成为用户正常运行条件。

## 3. 待评审的产品取舍

| 议题 | 推荐默认 | 不接受时的影响 |

| HDR/高刷/跨 GPU | 单独能力与质量档，不以单屏通过外推 | 扩大首版测试成本，发布时间后移 |

这些是评审内容，不是本次工作的中途许可请求。设计包已经完成；评审结果应作为后续 Claude Code 的输入。

## 4. 推荐的最小可行架构

**Core + Guard + 按需 Settings，D3D11/HLSL + DirectComposition，统一材质引擎；WGC 为生产后端（D03），DXGI 只做对照。** 首个可用版本支持单屏 SDR、固定/运行应用、基础预览、时钟日期、设置持久化与系统恢复。保留 Explorer/DWM 和系统快捷键。通知为补充层；桌面组件先公开窗口模式；托盘桥接、WorkerW、HDR 等以能力闸门逐个加入。

如果托盘接管、Win+D 桌面层或实时采样失败，明确减少功能，保留可靠共存版。不能为了表面满足需求把私有 Shell 内部机制升级为不可替代的核心依赖。
